Multi-Agent Travel Coordinator

Describe a trip in plain English and get back flights, hotels, and activities that fit together in time. Three of us built it over a weekend at SanD Hacks.

Result
Winner, Multi-Agent Systems Challenge. The weekend build ran a LangGraph supervisor and three search agents over NATS, all in Docker Compose.

The problem

Planning a trip with more than one leg means checking flights on one site and hotels on another, then making sure your check-in lines up with when you land. Getting that wrong costs money.

How a request moves

  1. The React UI sends your request to a FastAPI supervisor.
  2. The supervisor runs a LangGraph workflow: classify what you're asking for, pull out the details (cities, dates, budget), search, then check the results and return.
  3. For the search step, it sends messages over Cisco AGNTCY's agent-to-agent (A2A) protocol, carried by NATS, to three separate agents: flights (Google Flights), hotels (Google Hotels), and activities (Google Local), all through SerpAPI.
  4. Each agent runs its own small LangGraph and returns JSON.
  5. The supervisor drops hotels rated under 3.7 overall or under 4.0 for location. It adds a 2-hour buffer (configurable) to the flight's arrival time and keeps only hotels whose check-in has opened by the time you get there, then picks the cheapest flight plus hotel total. The UI turns that plan into cards.

Each search agent is its own service with its own A2A card. The whole stack (UI, supervisor, three agents, NATS, and an optional ClickHouse and Grafana setup) runs with Docker Compose.

When something is missing, like a check-in date, the supervisor asks for it instead of guessing. If it finds flights and hotels but no pair fits the timing rule, it says so and suggests an earlier departure or a later check-in.

My part

I set up the project's starting point. Rather than write the agent plumbing from scratch, I brought in Cisco's open-source CoffeeAGNTCY reference app, which already had A2A agent servers, a LangGraph supervisor, NATS and SLIM transport, a React UI, Docker Compose, and a Grafana and OpenTelemetry setup. I configured its environment (model and API keys) so the stack ran for the team, and we reworked its coffee-trading agents into the flight, hotel, and activity agents.

I also did the initial testing. As the pieces came together, I ran early trip requests through the supervisor and the three search agents to check that each one answered over A2A and that the plan it returned held together.

Next
